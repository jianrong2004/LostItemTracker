2. Admin Module Use Cases

2.1 Authentication

IDUse Case NameActorDescription
UC-ADM-01Admin LoginAdminAdmin logs in with email and password
UC-ADM-02Admin RegisterAdminNew admin registers an account
UC-ADM-03Admin LogoutAdminAdmin logs out and returns to Role Selection

UC-ADM-01: Admin Login

Preconditions: User has selected Admin role; Admin account exists in Firestore with role='admin'; Email is verified
Main Flow:
1. Admin enters valid email and password
2. Admin taps "Login"
3. System validates credentials and role
4. System navigates to Admin Dashboard (Admin Home Page)
Alternative Flow 3a - Invalid credentials: System shows error message; Admin remains on login page
Alternative Flow 3b - Non-admin account: System signs out and shows "Access denied. This account is not an admin account"
Alternative Flow 3c - Email not verified: System signs out and prompts to verify email
Postconditions: Admin is authenticated and on Admin Dashboard

UC-ADM-02: Admin Register

Preconditions: User is on Admin Login page; No existing admin account with same email
Main Flow:
1. Admin taps "Register" link on login page
2. Admin fills in registration form (email, password, full name, etc.)
3. Admin submits registration
4. System creates Firebase Auth account and Firestore user document with role='admin'
5. System redirects to Admin Login page (email verification may be required)
Postconditions: New admin account created; Admin can log in after email verification

UC-ADM-03: Admin Logout

Preconditions: Admin is logged in and viewing any admin page
Main Flow:
1. Admin opens side drawer (menu icon)
2. Admin taps "Logout" button
3. System displays confirmation dialog
4. Admin confirms logout
5. System signs out and navigates to Role Selection page
Postconditions: Admin is signed out; Role Selection page is displayed

5. Test Execution Notes

  • Pre-requisites: Firebase project configured; Test admin and user accounts created; Email verified for both
  • Test Environment: Android/iOS device or emulator with network access
  • Data: Ensure sample lost_item_reports, found_item_reports, lost_item_claims exist for full flow testing
  • Export Testing: Verify PDF/CSV appear in device Downloads folder (use downloadsfolder plugin)
  • Map Testing: Location permissions required for map and location selection
  • Photo Testing: Camera/gallery permissions required for report and claim photos
